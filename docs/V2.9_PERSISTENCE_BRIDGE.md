# TOOLIXA V2.9 — Persistence Bridge

## What changed

1. The Command Center reads the protected `/api/admin/settings` endpoint on load.
2. When a `commandCenter` snapshot exists in `SiteSetting`, it is merged into the dashboard state.
3. The Save changes button sends the current dashboard snapshot to the same protected endpoint.
4. When the database is not configured or unavailable, the dashboard stores the snapshot in browser `localStorage` and explicitly displays local fallback status.
5. The health endpoint reports `2.9.0`.

## Database setup

1. Copy `.env.example` to `.env` for local development and configure a real PostgreSQL `DATABASE_URL`.
2. Configure `NEXTAUTH_URL`, a strong `NEXTAUTH_SECRET`, `ADMIN_EMAIL`, and `ADMIN_PASSWORD_HASH` in server-side environment settings. Never expose these as `NEXT_PUBLIC_*` variables.
3. Install dependencies using `npm install`.
4. Generate the Prisma client: `npm run db:generate`.
5. For a new development database, create and review a migration using `npm run db:dev`; commit the generated migration directory.
6. For deployment after migrations have been committed, run `npm run db:migrate`.
7. Test an authenticated admin save and reload, then confirm the `SiteSetting` row with key `commandCenter` exists.

## Security and product limitations

- The endpoint checks the server-side Super Admin session. The database is not queried until authorization passes.
- If PostgreSQL is not configured, the client fallback is only browser-local. It is not shared across devices or users.
- The snapshot contains dashboard configuration, not uploaded file contents or secrets. Do not add credentials or API keys to the snapshot.
- This does not yet apply theme settings to the public storefront, translate tool overrides into `ToolConfig` rows, implement full CMS publishing, or connect billing and media storage.
- No successful production build or live database test is claimed from this environment.
